# Intern v0.1.0-alpha.11

This is an alpha release for Windows x86-64. It is deliberately published as a
GitHub **latest** release, not a GitHub prerelease, so installed clients can
fetch the updater manifest at `/releases/latest/download/latest.json`. The
version and this note still make its alpha status explicit.

## Read this first

- **Coming from alpha.10? Download this installer once, by hand.** Intern's
  home moved to `z-brenner/intern`. alpha.10 looks for updates at its old
  address and trusts only the old signing key, so it cannot update itself to
  this release. Install this one over alpha.10. Your queue, history, settings
  and learned spellings are kept.
- **Updates are signed with a new key.** From this release on, an installed
  Intern accepts only updates signed by the key whose ID is `23576C5DEB2D7F57`.
- **Going back to alpha.10 is not supported.** This release records failure
  reasons alpha.10 does not know, and alpha.10 cannot list a queue that holds
  one.

## What is new

### Names you can trust more

- **Accented text no longer stops the queue.** A character such as é, §, •, °
  or ½ near a date used to crash validation and pause everything. French and
  German invoices and many contracts hit it.
- **A document's own date is recognised.** "This Consulting Agreement dated…",
  "Contractor" and "Pursuant to Section 9.2… effective" used to be read as
  references to another document. The right date was then held back, or quietly
  replaced. A date cited from another agreement is still not taken.
- **Due dates, impossible years and ambiguous dates go to review instead of
  into the name.**
  - A date the document labels as a due, renewal or expiry date is not used as
    its own date.
  - A year like 2625 (an OCR misread) is flagged.
  - A date written only as `03/04/2026`, which could be read either way round,
    is flagged unless the document settles it.
- **Better filenames:**
  - ALL-CAPS letterhead names are written in title case: "Orion Glass Studio
    Inc.", not "ORION GLASS STUDIO INC.". Initialisms such as KPMG and IBM are
    kept.
  - A name never says "between" with only one party.
  - Folder names never end in a space or a dot.
  - The same party spelled two ways is named once.
- **Scans read better.** OCR now keeps the lines and paragraphs of a page, so
  labelled dates and headings on a scan are found the same way as on a typed
  PDF. A clearly readable page is read in one pass instead of up to five,
  which made four of the six test scans 2.4–6× faster to read. On the
  measured set of test documents, correctly named parties rose from 15 of 19
  to 16 of 19, with no fewer dates correct and no document filed under a trap
  date.

### More of what you actually file

- **New formats:** Word `.doc` and `.rtf`, OpenDocument `.odt`/`.ods`/`.odp`,
  PowerPoint `.ppt`, Excel `.xls`, and `.csv`. Watched folders pick them up too,
  and Office lock files are still ignored.
- **Password-protected files** are named as such ("This file is
  password-protected. Remove the password and add it again.") instead of
  failing with a generic error.
- **Outlook and email:**
  - HTML-only `.msg` messages are read properly instead of as hex.
  - Accented subjects survive.
  - Message dates use the local date the message was sent, not UTC, which
    could be a day off.
- **Large spreadsheets** whose facts sit in the first rows can be Ready rather
  than always going to review.
- **Windows-1252 text files** read correctly.

### Reviewing is faster

- **Drag and drop onto the window works.** It silently did nothing before.
- **Approve is always on screen** at the default window size, and the
  inspector no longer scrolls away in a long queue.
- **Keyboard-first review:**
  - Ctrl+Enter approves.
  - Up/Down or J/K move between documents.
  - Enter edits the name.
  - Alt+K keeps the original.
  - After each decision the next undecided document is ready.
- **Undo from the toast** after "Apply all ready", with progress while it runs.
- **Open** and **Show in folder** for documents in review, ready, and filed.
  Completed items show the name each document was filed under.
- **Analyze again** after you edit or sign a document.
- **The right actions for each document:** for example, Retry is no longer
  offered where it cannot work.
- **Filename problems** are explained inline as you type, before anything is
  sent.
- **Status says what is happening:** "Reading document…", "Proposing a name…"
  or "Renaming…", instead of "Processing (0%)".

### Working with your own firm and Windows

- **Your organisation's names.** List your firm's names in Settings. When a
  document names your firm and someone else, the filename and the party folder
  use the other side.
- **Send to → Intern** from Explorer, and Intern adds the files you send it.
- **Adding a batch skips what it cannot read.** One `.zip` among 25
  attachments no longer rejects all 25, and you are told what was skipped.
- **No blank window at sign-in.** With Run in background on, Intern starts
  quietly in the tray.
- **Startup problems are reported.** If Intern cannot start, it says why
  instead of vanishing.

### Reliability you do not have to think about

- **Watched folders no longer lose documents:**
  - Files that arrive while Intern is off, or during an update, are processed.
  - A document you remove or cancel stays removed.
  - New files are picked up within about half a minute, once they have
    stopped changing for ten seconds.
- **Undo always works:**
  - A rename that met a file open in Acrobat or Word can be retried.
  - Undo works again after an undo that could not finish, and is no longer
    refused while another document is being read.
- **Failures explain themselves.** A problem with one document fails that
  document and says why. Only problems that would affect every document pause
  the queue, and the banner says what to do.
- **Corporate networks:** the model download and hosted models now trust the
  certificates your organisation installs on Windows, so networks that inspect
  HTTPS traffic no longer break setup.
- **Faster launch.** Intern checks the whole 1.28 GB model file once after an
  install or update, not every time it starts.
- **Cancel is clean.** Cancelling a document no longer restarts the model
  repeatedly or pauses the queue.
- **Choosing a hosted model frees memory.** The local model is no longer kept
  loaded.
- **Hosted billing problems pause the queue once.** They no longer burn
  through your backlog one paid request at a time. A provider's Retry-After
  is honoured, up to two minutes.
- **History export** includes every row, opens correctly in Excel, and cannot
  carry spreadsheet formulas.
- **Logs for support.** Model and parser logs are kept under
  `%LOCALAPPDATA%\com.intern.app\logs`. They are designed never to contain
  document text.

### Privacy you can check

- **The automatic update check can be switched off** in Settings. The manual
  button always works.
- **The download page now lists every request Intern can make.** These are
  the one-off model download, the update check, a hosted model if you choose
  one, and Microsoft sign-in and Graph only in builds provisioned for
  SharePoint.

## Download, model, and update details

Supported target: **Windows 10 or 11, x86-64**, using the per-user NSIS
installer `Intern_0.1.0-alpha.11_x64-setup.exe`. It does not require
administrator rights. The installer contains the local parser and runtime but
not the 1.28 GB local text model. On first run, Intern downloads that pinned
model only after you ask it to, or lets you choose an existing verified copy.

With the local model (the default), document text, OCR output, and prompts
stay on the machine. A hosted model, if you turn one on, receives the distilled
text of each document. This build makes no Microsoft connection at all.

The client installs only an updater payload whose detached Minisign signature
verifies against the public key compiled into the application (key ID
`23576C5DEB2D7F57`). Before creating release evidence, the release workflow
independently verifies:

- the exact installer;
- its detached signature;
- the URL, version, and signature recorded in `latest.json`.

`SHA256SUMS.txt` covers every distributable release file exactly once. It
leaves out itself and `release-evidence-manifest.json`, to avoid a checksum
cycle. The evidence manifest hashes the checksum file. It also binds:

- the installer and updater manifest;
- the runtime inventory and notices;
- the SBOMs;
- the smoke, evaluation, and fidelity evidence;
- the logs.

Verify the installer provenance as well:

```sh
gh attestation verify Intern_0.1.0-alpha.11_x64-setup.exe --repo z-brenner/intern \
  --signer-workflow z-brenner/intern/.github/workflows/release.yml
```

The installer is **not Authenticode signed**: this project has no Windows
code-signing certificate. Windows SmartScreen may warn about an unrecognized
app even when the updater signature and GitHub provenance check pass. PCs with
Smart App Control in enforcement mode block it. Treat the warning seriously,
verify the checksum and provenance, then use **More info** → **Run anyway**
only if you trust the release.
