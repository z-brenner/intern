# Intern v0.1.0-alpha.13

This is an alpha release for Windows x86-64. It is deliberately published as a
GitHub **latest** release, not a GitHub prerelease, so installed clients can
fetch the updater manifest at `/releases/latest/download/latest.json`. The
version and this note still make its alpha status explicit.

## Read this first

- **Coming from alpha.12, Intern updates itself.** This release uses the same
  update address and the same signing key (ID `23576C5DEB2D7F57`). The
  automatic check or **Check for updates** offers it. Your queue, history,
  settings and learned spellings are kept. From alpha.10 or earlier, download
  this installer once, by hand, as the alpha.11 notes explain.
- **Two new models to download.** Intern now reads with **Qwen3.5 9B**
  (5.29 GiB), and with **Qwen3.5 4B** (2.55 GiB) while the 9B is still
  arriving or the computer is short of memory. Neither is the file alpha.12
  used, so after the update Intern shows its setup screen again and asks to
  download them: the 4B first, which is all you wait for, then the 9B in the
  background while you work. The alpha.12 files, Qwen3.5 2B and Bonsai 2 2B
  if you had it, are not deleted; nothing in Intern ever deletes a model
  file. You can remove them by hand from Intern's models folder.
- **Readings take longer, on purpose.** On the same 26 contract pages on a
  4-core machine, the 4B read a document in about two and a half times the
  time the 2B took (37 s against 15 s at the median), and the 9B in about
  four and a half times (68 s). That trade was made because the 2B was not
  right often enough: on three sets of real letters, notices and invoices
  the 9B names 22, 21 and 11 of about 60 documents right where the 2B named
  16, 17 and 11, and the 4B 18, 16 and 12
  (`bench/reports/model-qualification-2026-11`). Intern still reads in the
  background, one document at a time, with half the processor's threads.
- **The 9B needs about 10 GB of memory free.** A 16 GB laptop has that with
  little else open, and not with a browser and an office suite at work. When
  it does not, the 4B reads instead - it needs about 6.5 GB - and the 9B
  reads those documents again once memory comes back, unless you have acted
  on them first. The review panel says which model read a document, and
  whether it will be read again.
- **The quick model's names still wait for your check.** As in alpha.12,
  a name the quick model gives is never filed on its own: the 4B was
  measured on four sets of real documents and filed about one wrong name
  for every right one at any setting of the review gate, so its readings
  go to review, and the 9B reads them again when it can.

## What is new

### A larger model, and the rules that let it through

- **Qwen3.5 9B and Qwen3.5 4B replace Qwen3.5 2B and Bonsai 2 2B.** Both
  run on the upstream llama.cpp build the 2B already ran on. Six candidate
  models in the 4B-9B class were measured live on InternBench's 77 documents
  and on three sets of real documents; the two Qwen3.5 models were the only
  ones that named more documents right than the 2B, and the 9B the most.
  With the rules below, the 9B names 70 of InternBench's 77 documents right
  (the 2B 71, the 4B 64), 19 of 42 real contracts in the third CUAD sample
  (the 2B 14), and 22, 21 and 11 of the three real sets (the 2B 16, 17 and
  11). On a fourth real set gathered after every rule was written, the lead
  is smaller: 15 of 58 against 13, with the parties right on 41 against 30.
  The larger quantizations of the same models (UD-Q4_K_XL) named no
  more documents right, so the Q4_K_M files ship; speculative decoding
  gained nothing measurable on this processor and is not used.
- **A party's role the document does not spell out is read from the model.**
  The 2B labelled who issued, received or was the subject of a document
  poorly, so Intern only used a role the document's own wording confirmed,
  and otherwise named a file without a joining word ("Invoice - WPTV") or
  with the wrong side ("Notice for Internal Revenue Service"). The larger
  models label roles right far more often than the wording confirms them, so
  where the document settles nothing Intern now reads the model's roles - an
  invoice "from" the party it called the seller, a notice "for" the party it
  called the client - and holds such a name for your check, since it rests on
  the model alone. Where the document's wording contradicts the model, the
  model's reading is not used.
- **A title's number is no longer part of the type.** "Invoice No. 2248",
  "Invoice #PMr0197", "Quarterly Business Review - Q3 2026" and "January 1,
  1997 Invoice" name one copy; the type names the kind, and the number stays
  in the description. A numbered kind ("Amendment No. 3", "Change Order No.
  7") keeps its number.
- **The review gate is stricter.** Intern sends a reading to review when
  the model was unsure of its date or a party's name. A larger model is
  surer of its wrong names than the 2B was: at the 2B's threshold the 9B
  would have filed 16 wrong names of 42 on the four real sets, so the
  threshold moves from 0.5 to 0.7, where it files 2 of 15. More right names
  wait for your check as a result (37 of InternBench's 77 are filed where
  the 2B filed 65).

### Other changes

- **Both models run on one runtime.** The PrismML build that read Bonsai's
  weights is still packaged in this release and runs nothing; it will be
  removed in a later one.
- **Candidate models can be measured on GitHub runners.** A laboratory
  workflow runs InternBench and the real-document sets live for any set of
  candidate model files, in parallel, and gates nothing.

## Known limitations

- **The first download is larger.** 2.55 GiB before the first document, and
  5.29 GiB more in the background, against 517 MB and 1.28 GB in alpha.12.
- **The 9B does not fit beside a busy desktop.** With less than about 10 GB
  of memory free it does not load, and the 4B reads instead. Settings says
  which model is reading.
- **Real documents are still mostly reviewed, and a few wrong names are
  filed.** On the three real sets the 9B names about a third of the
  documents right; most of the rest go to review with a name to correct.
  Automatic renaming files only what passes every check, and on the four
  real sets that was 7, 3, 2 and 3 names, of which 2, 0, 0 and 0 were wrong
  (the 2B filed 9, 8, 5 and 6 with 1, 1, 2 and 1 wrong). The 9B is surer of
  a wrong name than the 2B was, so its gate is stricter and fewer names are
  filed at all. Keep automatic renaming off until you have seen how it reads
  your documents.
- **Hosted models still use the previous pipeline.** If you turn on a hosted
  model, it reads through the previous digest pipeline.
- **Every InternBench figure is from invented documents** on a Linux test
  machine, not from your documents or a Windows laptop.

## Download, model, and update details

Supported target: **Windows 10 or 11, x86-64**, using the per-user NSIS
installer `Intern_0.1.0-alpha.13_x64-setup.exe`. It does not require
administrator rights. The installer contains the local parser, OCR and
inference runtime but not the local text models, Qwen3.5 9B (5.68 GB) and
Qwen3.5 4B (2.74 GB). On a new install nothing is downloaded until you ask:
Intern then fetches the 4B first and the 9B in the background, or uses
existing copies you choose once their length and SHA-256 match the manifest
built into the installer.

With the local model (the default), document text, OCR output, and prompts
stay on the machine. A hosted model, if you turn one on, receives the distilled
text of each document. This build makes no Microsoft connection at all.

The client installs only an updater payload whose detached Minisign signature
verifies against the public key compiled into the application (key ID
`23576C5DEB2D7F57`). Before creating release evidence, the release workflow
independently verifies:

- the exact installer;
- its detached signature;
- the URL, version, and signature recorded in `latest.json`.

`SHA256SUMS.txt` covers every distributable release file exactly once. It
leaves out itself and `release-evidence-manifest.json`, to avoid a checksum
cycle. The evidence manifest hashes the checksum file.

Verify the installer provenance as well:

```sh
gh attestation verify Intern_0.1.0-alpha.13_x64-setup.exe --repo z-brenner/intern \
  --signer-workflow z-brenner/intern/.github/workflows/release.yml
```

The installer is **not Authenticode signed**: this project has no Windows
code-signing certificate. Windows SmartScreen may warn about an unrecognized
app even when the updater signature and GitHub provenance check pass. PCs with
Smart App Control in enforcement mode block it. Treat the warning seriously,
verify the checksum and provenance, then use **More info** → **Run anyway**
only if you trust the release.
