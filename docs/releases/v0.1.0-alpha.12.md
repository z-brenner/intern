# Intern v0.1.0-alpha.12

This is an alpha release for Windows x86-64. It is deliberately published as a
GitHub **latest** release, not a GitHub prerelease, so installed clients can
fetch the updater manifest at `/releases/latest/download/latest.json`. The
version and this note still make its alpha status explicit.

## Read this first

- **Coming from alpha.11, Intern updates itself.** This release uses the same
  update address and the same signing key (ID `23576C5DEB2D7F57`). The
  automatic check or **Check for updates** offers it. Your queue, history,
  settings and learned spellings are kept. From alpha.10 or earlier, download
  this installer once, by hand, as the alpha.11 notes explain.
- **Nothing to download again.** Your documents are still named by the
  same pinned Qwen3.5 2B file (1.28 GB). On the first launch after the update,
  Intern checks that whole file once. A second, optional quick model is
  offered in Settings and is downloaded only if you ask for it.
- **Intern now works between two folders, and needs both.** Documents in the
  *input folder* are processed; approved ones move to the *output folder*
  under their new name. If alpha.11 was watching a folder and filing into a
  destination, those become your input and output folders, with nothing to
  do. Otherwise Intern asks on its first launch, offering your destination
  again as the output folder, and cannot be used until both are chosen.
  Neither folder may be inside the other.
- **Adding a file now copies it.** Add files, Add folder, a drop on the window,
  and **Send to > Intern** copy files into the input folder. The originals
  stay where they were, untouched. In alpha.11 the file you added was the one
  renamed.
- **Intern now renames two kinds of file without asking.** Both renames happen
  in the input folder, are marked in the file's name, and can be reversed:
  - A document Intern cannot read for a reason of its own is renamed
    `NEEDS REVIEW - <name>` in place and waits in review. Reasons include a
    password, a damaged or mislabeled file, or a file too large to read.
    **Keep original** removes the prefix.
  - A file whose exact bytes Intern has already filed is moved into the
    output folder as `COPY - <the original's filed name>`, even with
    automatic renaming off. **Undo** puts it back.
- **Going back to alpha.11 is not supported.** A document read by the new quick
  model carries a review reason alpha.11 does not know, and alpha.11 cannot
  list a queue that holds one. alpha.11 also knows nothing of copy filings or
  `NEEDS REVIEW` renames.

## What is new

### Names built from facts the document states

- **The local model now gives facts, not the name and description.** It
  gives the type, the date, the parties and their roles, and the subject,
  each with the ID of the line in the document that states it. Intern checks
  every fact against what the model was shown, then writes the filename and
  description itself. A fact nothing the model was shown supports is not
  used.
- **A description says only what the document says.** Every word, whole
  number, currency symbol and percent sign in a subject or key fact must
  appear in the text the model read. Stray invisible characters, such as a
  zero-width space, are kept out of names.
- **Measured on InternBench's 77 synthetic documents**, replaying the new
  pipeline against the previous one on the same pages
  (`bench/reports/2026-10-07-phase3-compare.md`): correct filenames 26 → 54,
  marked ready under a wrong name 30 → 15, filed under a trap date 11 → 1,
  sent to review 32.9% → 15.6%, and median time per document, as recorded on
  a 4-core Xeon, 38.9 s → 19.2 s. A later live run on the PrismML runtime
  this release ships named 52 correctly and marked 18 ready under a wrong
  name (`bench/reports/bonsai-linux-cpu-2026-10-27`).

### Pages read in reading order

- **Every page is read as blocks in reading order:** headings, paragraphs,
  tables with their rows and cells, and labeled fields. Intern decides how to
  read each PDF page separately. A plain page is read directly. Columns and
  tables are read by their layout. A scanned page, or a scanned region on a
  text page, is read by OCR.
- **Scans are read with PP-OCR,** which runs through ONNX Runtime 1.30.0 and
  ships in the installer. If it cannot load, Intern reads scans with
  Tesseract, as it did before.
- On InternBench's 72 documents of the time
  (`bench/reports/2026-10-07-phase2-compare.md`), text in reading order rose
  from 64.9% to 100%, labeled values found from 57.6% to 99.0%, and correct
  filenames from 19 to 24; OCR character error fell from 19.1% to 5.0%. A
  later comparison with newer PP-OCR models and two other engines, on all 19
  scanned InternBench documents, found nothing better at an acceptable cost,
  so the OCR settings are unchanged (`docs/ocr.md`).

### Two local models

- **Qwen3.5 2B names your documents; Bonsai 2 2B (517 MB) is an optional
  quick model.** A new install downloads the quick model first and opens the
  queue once it passes its checks, while Qwen3.5 2B downloads in the
  background with one line in the window showing its progress.
- **A name from the quick model always waits for you.** It is never filed on
  its own, even with automatic renaming on. Review says "Read by the quick
  model — check it, or wait for the accurate model to read it again". Qwen3.5
  2B reads the document again once it can, unless you have already acted on
  it. On InternBench's 77 documents, Bonsai 2 2B named 37 correctly and marked
  23 ready under a wrong name. Qwen3.5 2B named 52–54 correctly
  (`bench/reports/bonsai-linux-cpu-2026-10-27`).
- **Settings > Model:** **Automatic** (recommended) reads everything with
  Qwen3.5 2B, the quick model standing in only while the computer is short of
  memory. **Most accurate** uses Qwen3.5 2B whenever memory allows.
  **Fastest** reads everything with the quick model; every name still waits
  for you and is not read again. Each model has a line with its size, state
  and the one action it needs. The review panel says which model read a
  document and whether the reading is provisional.
- **Memory:** One model is loaded at a time. Qwen3.5 2B is loaded only when
  4 GiB of memory is available; if it is the only model installed, it reads
  regardless. A model is unloaded after ten minutes without a document, and
  the next document loads it again.
- **New runtime:** both models run on the PrismML fork of llama.cpp, release
  `prism-b10826-c9c34bc` (alpha.11 used llama.cpp b10361), started with
  `--cache-ram 0 -ub 256 --prio -1 --poll 0`. With the Bonsai models, turning
  the prompt cache off stopped the server growing by tens to hundreds of MB a
  document with unchanged replies, and `-ub 256` made documents 13–14% faster
  on processors without AVX-512. `--prio -1 --poll 0` keep the server at low
  priority, out of the way of your other work.
- **One model failing to start no longer stops the queue** if the other model
  is installed. Intern sets the failed model aside, shows its error in
  Settings, and the other model reads. **Try again** brings the failed model
  back. A download you paused stays paused after a restart.

### Input and output folders

- **Setup** lists the OneDrive and SharePoint folders already on the computer
  and can create an *Output* folder beside the input folder. Settings shows
  both folders at the top with **Change…**. The "Watch a folder" checkbox is
  gone; options for a folder shared with other computers are under
  **Advanced**. A new install turns on running in the background and at
  sign-in once the folders are saved; an updated install keeps its choices.
- **Adding:** folders are flattened, a taken name gets " (2)", a file already
  in the input folder is not copied again, and one in the output folder is
  refused. Each copy is written under a temporary name in a hidden `.intern`
  folder, checked against the original, then given its real name, and joins
  the queue at once. Files sent with **Send to** before setup wait and are
  copied in once the folders are chosen.

### Unreadable files and exact copies

- **Unreadable files go to review.** A password-protected, damaged,
  mislabeled or oversized document now waits in review instead of failing.
  When a failure could be the machine's (an unusable reply, a time-out, a
  reader crash), Intern first shows the machine works, by reading another
  document or with its own self-test, and blames the document only if it
  fails again. An outage stops the queue and renames nothing. In review,
  **Retry**, type a name and approve it, or **Keep original**.
- **Exact copies are filed as copies,** named after the original, with
  " (2)", " (3)" for later ones, and with no description record of their own.
  **Undo** returns one to the input folder to wait in review as a duplicate;
  **Process anyway** reads it like any other document.

### Reviewing the queue

- **One Queue view.** The separate Needs Review page is gone. The toolbar
  shows how many documents need review, and clicking that count takes you to
  each one in turn.
- **Clicking a row selects it; Details opens the review panel,** which stays
  open and follows the selection. Enter or F2 opens it at the name.
  Ctrl+Enter, Alt+K and Delete act only while it is open; J/K and Up/Down
  still move between documents.
- **The table copies like a spreadsheet.** Click, Shift+click, drag, a column
  heading or Ctrl+A selects cells. Ctrl+C or **Copy** puts them on the
  clipboard as tab-separated text and an HTML table, so they paste into Excel
  or Google Sheets one value per cell. Status is never copied, a cell that
  starts like a formula pastes as text, and the description has its own
  column.

### Other changes

- **SharePoint Description column:** Intern now includes a Power Automate
  flow you can import (`intern-description-flow.zip`, linked from
  `docs/sharepoint-descriptions.md`). It asks only for a SharePoint connection,
  a site and a library. Settings lists the four steps. Intern itself still
  makes no network request for this.
- **American English** throughout the interface.
- **Linux:** an Ubuntu 24.04 `.deb` is built and tested in CI. It is not part
  of this release and does not update itself (`docs/linux.md`).

## Known limitations

- **Some wrong names are still marked ready.** On InternBench, 15 of 77
  documents were marked ready under a wrong name (18 in the live run). With
  automatic renaming on, those would be filed without a check.
- **Hosted models still use the previous pipeline.** If you turn on a hosted
  model, it reads through the previous digest pipeline. The new pipeline has
  been measured only with the local model.
- **PP-OCR costs more than Tesseract.** It uses about 2.7× Tesseract's
  processor time per scanned page and about 0.6 GB of memory while reading a
  page, against Tesseract's 57 MB (`docs/ocr.md`).
- **Every InternBench figure is from invented documents** on a Linux test
  machine, not from your documents or a Windows laptop.
- **The Power Automate flow has not yet been verified** in a real Microsoft
  365 tenant.

## Download, model, and update details

Supported target: **Windows 10 or 11, x86-64**, using the per-user NSIS
installer `Intern_0.1.0-alpha.12_x64-setup.exe`. It does not require
administrator rights. The installer contains the local parser, OCR and
inference runtime but not the local text models, Qwen3.5 2B (1.28 GB) and the
optional Bonsai 2 2B (517 MB). On a new install nothing is downloaded until
you ask: Intern then fetches the quick model first and Qwen3.5 2B in the
background, or uses existing copies you choose once their length and SHA-256
match the manifest built into the installer.

With the local model (the default), document text, OCR output, and prompts
stay on the machine. A hosted model, if you turn one on, receives the distilled
text of each document. This build makes no Microsoft connection at all.

The client installs only an updater payload whose detached Minisign signature
verifies against the public key compiled into the application (key ID
`23576C5DEB2D7F57`). Before creating release evidence, the release workflow
independently verifies:

- the exact installer;
- its detached signature;
- the URL, version, and signature recorded in `latest.json`.

`SHA256SUMS.txt` covers every distributable release file exactly once. It
leaves out itself and `release-evidence-manifest.json`, to avoid a checksum
cycle. The evidence manifest hashes the checksum file. It also binds:

- the installer and updater manifest;
- the runtime inventory and notices;
- the SBOMs;
- the smoke, evaluation, and fidelity evidence;
- the logs.

Verify the installer provenance as well:

```sh
gh attestation verify Intern_0.1.0-alpha.12_x64-setup.exe --repo z-brenner/intern \
  --signer-workflow z-brenner/intern/.github/workflows/release.yml
```

The installer is **not Authenticode signed**: this project has no Windows
code-signing certificate. Windows SmartScreen may warn about an unrecognized
app even when the updater signature and GitHub provenance check pass. PCs with
Smart App Control in enforcement mode block it. Treat the warning seriously,
verify the checksum and provenance, then use **More info** → **Run anyway**
only if you trust the release.
