# Intern v0.1.0-alpha.18

Intern is an alpha release for Windows 10 or 11, x86-64.

## Less memory, less waiting

- **The quicker model holds about 1.3 GB less memory while it is loaded.** Qwen3.5 4B now reads its weights where the model file lies instead of keeping a second copy of most of them, as the accurate model has since alpha.17. On a 16 GiB Windows test machine its memory after a document fell from 4,514 MiB to 3,215 MiB; on Linux test machines its peak fell from 4,558–4,613 MiB to 3,260–3,315 MiB. It is the model a computer with less than about 8 GB of memory free reads with, so the saving lands where memory is tightest. It also reads a little faster: about 9% on Linux test machines limited to the AVX2 code path, about 4% on the Windows test machine. It named as many test documents right as before (165 of 291, against 159 and 165 for two runs of the earlier launch).
- **After an update, Intern no longer reads its 7.8 GB of model files through again to check them.** A model file is checked again only when its size, its date or the checksum Intern pins for it changes. The model's short self-test still runs once after each update, before the first document, because an update can change how the model is asked and launched.
- **At sign-in, a model that has passed its checks is not loaded until a document is waiting for it**, so Intern holds no model's memory while there is nothing to read. A loaded model is no longer unloaded for being idle while a document waits to be read.
- **A document on its way starts the model loading**: one added, dropped or sent to Intern, one arriving in a watched folder on this computer's own disk or in a synced folder you chose as one only you add files to, and one that arrived there while Intern was off. The model loads while the file settles, so the reading can start sooner. A file a teammate adds to a shared folder does not load the model on every computer watching it. How much sooner was not measured: at most the model's load, about 3–5 seconds on a test machine with the file already in memory, more from a cold disk.
- **Faded single-page photos and faxes are recognised (OCR) up to four times sooner.** A reading that is plainly the right way up no longer tries the page at three other turns, none of which could have read it better. On eight such test images, 2.2–10.3 seconds became 0.7–2.6 seconds. Every one of the 448 development documents reads exactly as before.
- **Re-analyzing a file that has not changed reuses the text Intern has just read from it** (the last 8 documents, kept in memory until Intern restarts).

## Better readings

- **Scans that carry somebody else's OCR text are read again when that text would read badly**: every line repeated because the text was laid over the scan two or more times, or prose torn into a cell per word. Intern's own OCR reads such a page where it matters — a page it would read anyway, or the first two pages and the last — and its reading is used when it is confident (75 or more). On the 32 development documents with such a layer, the text Intern extracted held the right date for 26 where it held 22, and the right parties for 30 where it held 23. Read live by the accurate model, 27 of those documents got 9 names right where alpha.17 got 7, and 4 were filed without your check, all of them right, where alpha.17 filed 1. Those documents take longer to read: 0.5–5.5 seconds more on each of the 18 that read new pages, and up to a second less on 10 that now read a page once instead of twice.
- **A case number's label no longer joins a document's type.** A subject line such as "Notice of Civil Penalty Assessment and Order Case No. WQ-2023-626" gives the type "Notice of Civil Penalty Assessment and Order", not "... and Order Case". The cleaner text above first showed this, on a test document filed without review under the longer type.
- **A blank page in a scan — the back of a duplex sheet, a separator — is no longer a reason to send the document to review.** A page counts as blank only if it looks it: all but one pixel in 10,000 within a few shades of its paper. A page with faint writing, grain or bleed-through on it still raises the doubt it did.
- **Fewer wrong names are filed without your check.** Four kinds of name that were filed now wait for you:
  - a letter named as the paper its subject line talks about ("Re: Review of the Connection Policy" filed as a "Review"): it is named a letter, and waits;
  - an invoice, receipt, statement, quote or order whose date is written only as the start or end of a period, such as a billing week. Review says "Date is a period's start or end";
  - a name that gives a party with no "from", "to" or "for" before it ("Purchase Order - Kestrel Instruments Ltd"), and a purchase order named from its vendor only because the vendor's name heads the page;
  - a party more than 70 characters long, which is rarely one name.

  On the 20 recordings of test documents these rules were written from (1,224 readings by both models), wrong names filed without a check went from 6 to 2, and from 1 to 0 for the accurate model; the two left are the quicker model's, whose readings are not filed on their own. No right name that was filed now waits. The cost falls on documents outside those recordings: a right name of one of these kinds waits too.
- **Notices, circulars and reports are named by who they come from more often.** A circular or memorandum addressed to a class of people is named from the office that sent it ("Mortgagee Letter from HUD", not "to All FHA-Approved Mortgagees"; an annual report from its company, not "for Fellow Shareholders"). A notice or a record whose one party the model read as its issuer is "from" that party, where Intern wrote "for" by default; a notice is "for" a party only the model called its recipient. All of these names wait for your check as they did: what changes is the name you are shown.
- **Court captions, payment slips and one-word company names.** The person sued in their office is a party ("Notice of Appeal between City of Philadelphia and Doug Burgum"); "Defendants" and "Debtors" before a name are no longer part of it. An invoice with a tear-off payment slip is named from the supplier the slip pays, not from the customer it is addressed to. A letter to a person at a company whose name is one coined word ("PacifiCorp") is named to the company, and waits.
- **A duplicate invoice is filed again.** An invoice stamped "DUPLICATE" or "COPY" under its title was held because the model answered "Invoice Duplicate", which no line says. It is read as the invoice its title says; six such readings in the recordings are now filed, all of them right.
- **A title no longer runs into the date box beside it** ("Certificate of Liability Insurance", not "... Insurance Date (Mmddyyyy)"), and a sentence that opens "This letter sets out ..." is no longer taken for a type.
- **Counted on those 20 recordings, 694 names are right where 661 were, and 118 right names are filed without a check where 112 were.** These are the documents the rules were written from, so that is the most the rules can be said to do. On documents they were not written from, see below: one name gained and one lost.

## In review

- **In review, other parties the document names are one click from the name.** They are shown under the name; a click puts that party in place of the one the model chose (the second side of a "between" name). Only parties the document itself names are offered, never your own organization or someone only copied in. Ctrl+Z takes a choice back. Choosing another party, by a click or by typing it, is not learned as a spelling to apply to later documents, and a document filed by party goes in the folder of the party you chose.
- **Ctrl+Z changes only the field you are in.** In review, Ctrl+Z in the description, in the queue's filter or after a click on the panel undid the last edit to the name instead and put the cursor there, where the next Enter filed the document under the half-undone name. In Settings it could undo an unsaved setting the same way. And while Settings or Rename history is open, nothing behind it takes the cursor: Tab stays in the dialog, and the review window behind it waits until you close it.
- **A name or a description you typed and did not file is still there when the review panel comes back.** It was lost whenever the panel left the screen: closed by its own button or the Details button, or by itself when the window was made narrower than 1100 pixels - snapped to half of a 1920-pixel screen - or a narrow window was made wider. Both fields came back as Intern's proposal. What you typed now stays with its document until you file the document, decide it some other way, or have it read again.
- **When a document changes by itself while you are typing its name or description, what you type next is not taken as a command.** A document changes by itself when Intern reads it again - it does that for every provisional reading once the accurate model is ready - when another computer files it, or when its file is taken from the Queue folder; and the review panel closes by itself when the window changes width. The field you were typing in went, the cursor with it, and the rest of your sentence was read as keys: J and K moved to other documents, Enter opened one and filed it, Ctrl+Enter approved one. What you had typed now stays on screen, read-only, with the cursor in it - in the review panel, or above the queue when the document or the panel has gone - and nothing typed there does anything, Tab included: Escape, or a click, leaves it. It stays until you dismiss it. Two rare cases are not covered, and behave as they did: a decision of your own for another document that finishes in the same instant as the change, and an Enter for the document itself that is on its way as Intern reads it again. In both, what you had typed is kept, but the keys typed next are read as keys.
- **A name or a description you typed is no longer thrown away when Intern reads the document again by itself.** The panel shows the new reading, and what you had typed is kept above it, read-only, until you discard it. Analyze again still starts from Intern's reading, as before.
- **Rename all ready leaves alone a ready document whose name or description you typed and did not file.** It filed Intern's proposal for it and said "Renamed 3 documents"; what you had typed was gone. The button now counts what it will rename, and afterwards says how many it left for you.
- **Back to Intern's proposal takes back what you typed for a document.** Because what you type is now kept, closing the panel with Escape no longer throws an edit away, and Ctrl+Z has nothing to undo in a name shown again: letters deleted from a name by mistake stayed deleted, and Enter filed the spoiled name. The link is above the name whenever the name or the description differs from Intern's proposal.
- **The review drawer opens only when you ask for it.** In a narrow window, a drawer you had opened once opened again by itself the next time the window was made narrow, over whichever document was selected by then and with the cursor in its name, so the Enter meant to open a document filed it.
- **When the document you have open leaves the queue by itself, the space bar or Enter typed next renames nothing.** A document leaves by itself when its file is taken from the Queue folder or another computer files it. The cursor then went to Rename all ready, and the next space bar renamed every ready document. It now goes to the Queue or Completed button above the table, where the space bar and Enter rename nothing - and it is never taken out of a field you are typing in. After you remove a document yourself with Delete, it stays in the table, where the arrow keys go on.
- **Not fixed: a click made in the quarter-second after a document changes by itself lands on whatever has moved under the pointer.** That was so before this release. The text now kept on screen changes where it can happen. A click on its way to Close review, as the open document leaves the queue, landed on Rename all ready; with the cursor in a field it no longer does. A click on its way to the name field, as the document is read again, can land on the kept text's Discard, and what you had typed is gone (it was always gone before this release, whatever you clicked). In a window 880 to 900 pixels high, a click on its way to Keep original can land on Approve & rename and file the new reading: before, only when the new reading made the panel taller; now after any new reading.

## Spellings learned from your edits

- **A spelling Intern learned from your edits still fills in names, but a name it changes waits for you until you choose "Use on its own" for that spelling.** That includes every spelling learned before this update: with automatic renaming on, the documents those spellings rename wait for you until you have chosen "Use on its own" once for each spelling. Approving such a name does not count, however many you approve: a name can be right for one document while the spelling is wrong for the next. "Use on its own" is in Settings, under Learned spellings; a name waiting for a spelling says so in review and points you there. It first says that every later document Intern reads as naming the word will be named with the spelling and may be filed under that name without your check, then asks you to type the spelling to confirm it - case, accents, spaces and punctuation aside - and it approves and files no document. Until you choose it, a spelling is used only where the name shows it: a document whose name leaves out the party it respells is filed and reported under the document's own words. Documents already filed are not looked at again. A name waiting for a spelling says "Learned spelling" in the queue, and Settings shows the spelling as "In use · asks before filing". Putting the document's own words back, changing nothing else, makes Intern forget the spelling; "Forget" in Settings does too.

## On documents it has never seen

Before this release, 55 more public documents were gathered and their correct names written down by hand, and what would be measured on them was fixed in advance. The accurate model read 54 of them (one could no longer be downloaded as pinned). Nobody who wrote or reviewed a rule in this release had seen them; one caveat is given below.

- **19 of 51 names right**, the same count as alpha.17's engine gives from the same replies. This release's last rules changed seven of the 54: one name became right and one became wrong, both in review before and after. Type right on 47 of 54, date on 47 of 51, parties on 33 of 54.
- **3 names filed without your check, all 3 right.** alpha.17's engine files a fourth from the same replies, wrong: a consultation response named by the consultation's title. It now waits, named a letter, though still not from the right party. The caveat: that wrong name was known when this release's last rules were chosen. The rule that now holds it was written from a different document of the same kind, by reviewers who had not seen these 55, but it cannot count as a blind test of that rule.
- At alpha.16's review gate of 0.7 the same documents would have had 8 names filed, 3 of them wrong: the stricter gate alpha.17 adopted held two of the three wrong names, and two right ones, on documents it was not chosen on.
- 51 documents cannot certify a rate, and 94% of the 54 waited for a check. Expect most documents to wait for a quick look.

## Documents waiting for your check

From this release, Intern keeps with each reading what it asked the model, which model file answered and how the model was run. After a later update, documents still waiting for your check that nobody has acted on are validated again by the new release's rules from the model's stored reply, without asking the model again, when all three are unchanged. A rule a future release improves then reaches the documents already waiting. Documents read by earlier releases are left as they are.

## Updates

The installer is `Intern_0.1.0-alpha.18_x64-setup.exe`. Existing settings, queue records and model downloads are retained; upgrading from alpha.13 or later downloads no model.

The installer is **not Authenticode signed**. Windows may show a SmartScreen warning. Updater signatures, checksums and GitHub build provenance are verified before publication.
