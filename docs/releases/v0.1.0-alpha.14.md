# Intern v0.1.0-alpha.14

This is an alpha release for Windows x86-64. It is deliberately published as a
GitHub **latest** release, not a GitHub prerelease, so installed clients can
fetch the updater manifest at `/releases/latest/download/latest.json`. The
version and this note still make its alpha status explicit.

## Read this first

- **Coming from alpha.13, Intern updates itself.** This release uses the same
  update address and the same signing key (ID `23576C5DEB2D7F57`). The
  automatic check or **Check for updates** offers it. Your queue, history,
  settings, learned spellings and the two model files are kept: nothing new
  is downloaded. From alpha.10 or earlier, download this installer once, by
  hand, as the alpha.11 notes explain.
- **Real letters and notices get their names right more often.** On four
  sets of real letters, notices, invoices and office files, 234 documents in
  all, the 9B now names 92 right where alpha.13 named 67, and the 4B 71
  where it named 59. Most of the gain is on letters: a letter is now known
  by any greeting, dateline or sign-off, so a document with no title is a
  "Letter" rather than a "Document", and the organization a person writes
  to or from is read from the inside address, the signature block and the
  letterhead.
- **Reading is faster on a hyper-threaded machine.** The model now uses
  every logical processor, at most eight, where it used half of them. On
  two-core, four-thread test machines that cut the time per document by 16
  to 18%; a machine without hyper-threading reads as before. Intern still
  reads in the background at low priority.
- **The 9B loads with 8 GB of memory free, not 10.** Measured under a
  memory limit, the 9B keeps reading at its speed with about 6 GB and
  thrashes below that, so the floor comes down. A 16 GB laptop with a
  browser open now reads with the 9B where it read with the 4B before; with
  a browser and an office suite at work the 4B still stands in.

## What is new

### Letters, notices and captions

- **A letter in every layout.** A greeting in any form ("Dear" alone,
  "Gentlemen:", "To Whom It May Concern"), a dateline written short ("Dec.
  26, 1907"), or a sign-off over a signature ("Yours faithfully") names a
  document a letter when the model found no kind in it; an email by its
  header block and a notice by a heading opening on the word stand in the
  same way. Such a name still waits for your check, as the bare "Letter"
  did before.
- **A letter's organizations.** The inside address names the organization
  under the person in more of its forms (a name in capitals, a name with no
  company word, the organization a post is held at, the line over the
  person); a British layout, with the address above the dateline, is read
  as one; a person who signs is replaced by the organization under their
  post in the signature block, or by the letterhead. A second person's
  lines, a street, a city, a "cc:" line and a correspondence marking
  ("WITHOUT PREJUDICE", "By Post") are never read as an organization.
- **A letter is "to" its client**, never "for": "Warning Letter to Toledo
  Refining Company".
- **A type copied past its line** is cut back to the line's own words: a
  larger model copies a wrapped title and runs on into the paragraph under
  it.
- **Captions and titles.** A caption set "- against -" or in a table's
  cells is read; a notice whose model reading kept one side of the case
  takes the other side from the caption, never the court's own name or
  county; "Plaintiff's Notice of Motion" is a "Notice of Motion", "White
  Finding, Notice of Violation" a "Notice of Violation", and "trading as"
  and "d/b/a" are cut from a party's name.

All of it is deterministic, measured by replay on every recording of the
2B, 4B and 9B across InternBench, the four real sets and the contract
samples: 51 names right that were wrong, one lost (in review), and no
wrong name filed that was not filed before
(`docs/accuracy-research-2026-10.md`).

### Threads and memory

- **Every logical processor, at most eight** (`bench/reports/speed-linux-cpu-2026-11-05`).
  Four threads against two on a two-core, four-thread machine: prompt
  processing 9 to 19% faster and, on an Intel Xeon, decoding 43% faster,
  16 to 18% less time per document. The other settings tried (`-ub 512`,
  flash attention off, no memory mapping) were within noise, and a q8_0 KV
  cache was slower and changed the replies; they stay as they were.
- **The 9B's memory floor is 8 GiB.** Under a memory limit the 9B holds
  about 3.4 GB of its own and keeps reading 2.7 GB of its mapped weights;
  the rest of the mapped file is read once at load and reclaimed at no
  cost. At 6 GB it reads 20 to 30% slower than unconstrained; at 5 GB it
  thrashes.

### Other changes

- **Server settings can be measured on GitHub runners.** A laboratory
  workflow replays the recorded requests against one `llama-server` setting
  and the app's own on the same runner, alternated, and gates nothing.

## Known limitations

- **Real documents are still mostly reviewed, and a few wrong names are
  filed.** On the four real sets the 9B names 23, 28, 16 and 25 of about
  60 documents right; most of the rest go to review with a name to correct.
  Automatic renaming files only what passes every check: 7, 3, 2 and 3
  names on the four sets, of which 2, 0, 0 and 0 were wrong, unchanged from
  alpha.13. Keep automatic renaming off until you have seen how it reads
  your documents.
- **The thread count was measured on server processors.** The gain comes
  from the extra threads of a few cores; a laptop chip with efficiency
  cores was not measured, which is why the model takes at most eight.
- **The memory floor was measured on Linux.** Windows reclaims a mapped
  file's pages through its standby list rather than the page cache; the
  behaviour under a squeeze there was not measured.
- **Hosted models still use the previous pipeline.** If you turn on a hosted
  model, it reads through the previous digest pipeline.
- **Every InternBench figure is from invented documents** on a Linux test
  machine, not from your documents or a Windows laptop.

## Download, model, and update details

Supported target: **Windows 10 or 11, x86-64**, using the per-user NSIS
installer `Intern_0.1.0-alpha.14_x64-setup.exe`. It does not require
administrator rights. The installer contains the local parser, OCR and
inference runtime but not the local text models, Qwen3.5 9B (5.68 GB) and
Qwen3.5 4B (2.74 GB). On a new install nothing is downloaded until you ask:
Intern then fetches the 4B first and the 9B in the background, or uses
existing copies you choose once their length and SHA-256 match the manifest
built into the installer.

With the local model (the default), document text, OCR output, and prompts
stay on the machine. A hosted model, if you turn one on, receives the distilled
text of each document. This build makes no Microsoft connection at all.

The client installs only an updater payload whose detached Minisign signature
verifies against the public key compiled into the application (key ID
`23576C5DEB2D7F57`). Before creating release evidence, the release workflow
independently verifies:

- the exact installer;
- its detached signature;
- the URL, version, and signature recorded in `latest.json`.

`SHA256SUMS.txt` covers every distributable release file exactly once. It
leaves out itself and `release-evidence-manifest.json`, to avoid a checksum
cycle. The evidence manifest hashes the checksum file.

Verify the installer provenance as well:

```sh
gh attestation verify Intern_0.1.0-alpha.14_x64-setup.exe --repo z-brenner/intern \
  --signer-workflow z-brenner/intern/.github/workflows/release.yml
```

The installer is **not Authenticode signed**: this project has no Windows
code-signing certificate. Windows SmartScreen may warn about an unrecognized
app even when the updater signature and GitHub provenance check pass. PCs with
Smart App Control in enforcement mode block it. Treat the warning seriously,
verify the checksum and provenance, then use **More info** → **Run anyway**
only if you trust the release.
