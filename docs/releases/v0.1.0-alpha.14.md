# Intern v0.1.0-alpha.14

This is an alpha release for Windows x86-64. The installer is **not Authenticode signed**; Windows SmartScreen may ask before running it. The
in-app updater verifies its separate update signature.

## What changes

- **Use the document's own date.** Explicit lease and statement-of-work dates,
  and the start of an insurance policy period, take precedence over unrelated
  signatures, end dates and referenced agreements. Ambiguous evidence still
  waits for review.
- **File a report under its organization, not its signer.** A job title on the
  line below a signer's name now establishes that staff role. Recovery requires
  one clear organization in the shown letterhead; missing or ambiguous ownership
  waits for review. An explicitly named recipient or subject keeps their role.
- **Keep copied date fields out of document types.** A trailing effective-date
  field no longer becomes part of the type and repeats the date in the filename.
- **Avoid an unnecessary review for a supported abbreviation.** An omitted
  optional subject can be grounded by a unique expansion in the same shown
  passage, including a few checked action-word forms. Unsupported names,
  amounts, claims and ambiguous expansions still require review. Unstated
  abbreviations remain absent from the emitted filename and description.
- **Wait when neither installed model fits memory.** Intern keeps the document
  queued and allows a retry after memory is available, instead of loading a
  model that does not fit or marking a verified download as broken.
- **Test the same confidence policy the app uses.** Release evaluation now
  requests critical-value probabilities, checks that the server returned them,
  and enforces the app's 0.7 gate. The review ceiling and correctness thresholds
  have not been lowered.

## Models, updates and performance

The Qwen3.5 9B and 4B model files and upstream runtime pins are unchanged from
alpha.13. Existing verified model files remain usable. Accurate/Automatic still
use 9B when measured available memory allows; the fast tier's results continue
to require review. Neither model sends document contents to a hosted service.

The larger model remains a quality-versus-latency tradeoff. The original matched
PC experiment used four CPU cores, a 12 GiB memory cap and no swap: its median
was 55.77 seconds for 9B versus 13.97 seconds for 2B. Replaying the same responses
through the fixes improves 9B from 69 to 73 accepted filenames out of 77, from
74 to 77 correct dates, and from three to zero strict wrong-ready results.
The same replay leaves 2B at 67 filenames, 76 dates and one wrong-ready. These
are reported constrained-desktop results and recorded-response validation;
they are not fresh alpha.14 inference timings or an actual 16 GB laptop test.

The application-source Windows qualification passes native and installer checks
and completes 19 live documents: ten ready and nine held for review. The
same-recording control comparison changes only the SOW review decision, with
no new emitted fields or readiness loss. The release procedure separately
checks the exact versioned main tree, including installer and live-model
acceptance; these earlier qualification results retain their original scope.

This update preserves the existing local model setup, updater address and signing
key. Queue/history compatibility and installer data retention remain release
checks. Evidence, including known limits and the original failed runs, is in
[`docs/qa/post-alpha13-report-organization.md`](../qa/post-alpha13-report-organization.md).
